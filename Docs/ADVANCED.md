# 자세한 설정·개발 안내

일상적인 사용은 [README](../README.md)를 먼저 확인하세요. 이 문서는 기존 감시기 연결, 문제 점검, 복구와 개발 작업을 할 때 필요한 내용을 모았습니다.

## 설치 준비

macOS 13 이상에서 다음 도구를 준비합니다. README의 설치 명령은 소스를 받아 Mac에서 앱을 만드는 방식입니다.

1. **Codex CLI 설치·로그인:** 터미널에서 쓰는 Codex 프로그램입니다. [공식 설치 안내](https://learn.chatgpt.com/docs/codex/cli)에 따라 설치하고 로그인한 뒤 다음 명령으로 확인합니다.

   ```sh
   codex --version
   codex login status
   ```

2. **Xcode Command Line Tools 설치:** 앱을 만드는 Mac 개발 도구입니다. 아직 설치하지 않았다면 다음 명령을 실행하고 화면 안내를 따릅니다.

   ```sh
   xcode-select --install
   ```

설치·업데이트·제거 도구에는 Python 3.9 이상도 사용합니다. `python3 --version`으로 확인하세요. 메뉴바 앱과 감시 기능의 실행에는 Python이 필요하지 않습니다.

준비가 끝나면 [README의 처음 설치](../README.md#처음-설치)로 돌아가 설치 명령을 실행하세요. 소스를 이미 받은 경우에는 해당 `codex-usage-menubar` 폴더에서 `./Scripts/install.sh`를 실행하면 됩니다.

## 설치 위치와 갱신 간격

처음 설치하면 앱을 `~/Applications/CodexUsage.app`에 넣고, 메뉴바와 감시 기능을 로그인할 때 함께 실행하도록 등록합니다. 자동 사용은 꺼짐, 만료 알림은 켜짐으로 시작합니다. Mac에서 알림 허용을 선택하면 배너를 받을 수 있습니다.

기존 설치를 업데이트할 때는 등록된 앱 위치와 감시기 이름, 자동 사용·알림 선택, 사용 기록을 유지합니다. 등록된 앱이 `/Applications/CodexUsage.app`에 있는 경우에도 같은 위치를 사용하며, 해당 위치에 쓸 권한이 있는 환경에서 실행해야 합니다. 도구는 관리자 권한을 자동으로 요청하거나 권한을 확대하지 않습니다.

Codex CLI가 자동으로 검색되지 않으면 실제 실행파일 위치를 지정합니다.

```sh
CODEX_PATH=/example/bin/codex ./Scripts/install.sh
```

`/example/bin/codex`는 가상 경로입니다. 메뉴 사용량의 기본 갱신 간격은 5분입니다. 다음 예시는 2분으로 바꾸며, 최소 60초까지 설정할 수 있습니다. 자동 사용 감시기의 1분 확인 주기와는 별개입니다.

```sh
CODEX_USAGE_REFRESH_SECONDS=120 ./Scripts/install.sh
```

최신 소스를 받은 프로젝트 폴더에서 `./Scripts/install.sh`를 다시 실행하면 함께 업데이트됩니다. 도구는 새 앱을 준비한 다음 기존 메뉴와 감시기를 멈추고 교체합니다. 이전 사용 기록은 지우거나 오래된 사본으로 되돌리지 않습니다.

`./Scripts/uninstall.sh`는 메뉴와 감시기의 로그인 등록, 설치된 앱을 함께 제거합니다. 설정·사용 기록·백업은 보존하므로, 같은 설치 명령으로 다시 설치해도 이전 선택과 미확정 요청이 유지됩니다. `--purge`처럼 사용 기록까지 삭제하는 옵션은 제공하지 않습니다.

## 빠른 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 설치할 때 같은 이름의 폴더가 있다고 나옴 | 이미 받은 `codex-usage-menubar` 폴더에서 `./Scripts/install.sh`를 실행하세요. |
| 아이콘이 안 보임 | Finder의 사용자 폴더 → 응용 프로그램에서 CodexUsage.app을 열고, 메뉴바 관리 앱의 숨김 영역을 확인하세요. |
| `…`, `!`, `?` 또는 오래된 값 | `…`는 첫 조회 중, `!`는 조회 실패, `?`는 사용량 정보가 없는 상태입니다. 실패가 계속되면 CLI 설치·로그인·네트워크를 확인하고 새로고침하세요. 조회 실패는 남은 사용량이 0이라는 뜻이 아닙니다. |
| 자동 사용을 켤 수 없거나 사용되지 않음 | 설치가 완료됐는지와 [사용 조건](#자동-사용과-알림의-동작)을 확인하세요. |
| 설치가 중간에 멈춤 | 백업과 설치 기록을 보존하고 [실패·중단 후 복구](#백업과-복구)를 확인하세요. |
| 감시기 충돌 또는 알 수 없는 기록으로 설치 중단 | 기존 감시기가 두 개 실행 중인지, 인식할 수 없는 등록이나 미확정 기록이 있는지 확인하세요. 도구는 이를 무시하고 새 감시기를 만들지 않습니다. |
| 소비 결과 확인 필요 · 추가 사용 보류 | [결과가 불확실할 때의 처리](#결과가-불확실할-때의-처리)를 확인하세요. |
| 알림이 안 보임 | 시스템 설정 → 알림 → CodexUsage에서 허용하고, 배너 설정과 집중 모드를 확인하세요. 알림 등록이 성공해도 배너가 화면에 보이는지는 이 설정에 영향을 받습니다. |

메뉴의 날짜와 만료 시각은 Mac의 시간대를 따릅니다. 사용량은 기본 갱신 주기 외에 잠자기에서 깨어날 때도 다시 조회합니다.

## 자동 사용과 알림의 동작

등록된 감시 프로그램 하나가 정상 실행되고 **자동 사용**이 켜져 있을 때 다음 조건을 확인합니다.

1. 리셋권이 유효하고 만료까지 **20분 이하**입니다.
2. 기본 Codex의 **5시간 또는 주간 남은 사용량이 10% 이하**입니다. 별도 기능의 사용량 제한은 이 판단에 사용하지 않습니다.
3. 사용 직전 재조회에서도 같은 권과 만료 시각, 사용량 조건이 확인됩니다.

감시기는 Mac이 깨어 있고 로그인된 동안 1분마다 확인합니다. 표시된 다음 시도 시각은 조건부 예정이며, 정확한 시각의 실행을 보장하지 않습니다. 최종 사용 가능 여부와 결과는 Codex 서비스가 결정합니다. 메뉴 앱을 종료해도 감시기는 계속 실행되므로, 자동 사용을 멈추려면 메뉴의 **자동 사용**을 끕니다.

전원 종료·잠자기 중에는 확인·사용·알림을 실행하지 못합니다. 앱이 Mac을 깨우거나 이미 만료된 권을 되살리지는 않습니다.

**상세 → 만료 전 Mac 알림**은 자동 사용과 독립적인 설정입니다. 만료 1시간·20분·5분 전 단계에 알리며, 잠자기에서 깨어나면 현재 시점에 맞는 단계만 보내고 놓친 알림을 한꺼번에 보내지 않습니다. 사용 완료·이미 사용·해당 권 없음이 확인되면 그 권의 알림을 중단합니다. 알림 자체는 사용 완료를 뜻하지 않습니다.

## 기존 감시기를 앱으로 옮기기

`./Scripts/install.sh`가 기존 사용자 로그인 서비스에 등록된 **Python 감시기 `reset_credit_watcher.py` 하나**를 자동으로 찾아 인계합니다. 별도 설치 명령은 필요하지 않습니다.

이전 감시기를 멈춘 뒤 마지막 사용 기록을 다시 읽고, 같은 등록 이름을 앱의 감시 기능에 연결합니다. 기존 앱의 자동 사용 설정이 있으면 유지하고, 처음 앱으로 옮기는 경우에는 자동 사용을 끈 상태로 시작합니다.

서로 다른 감시기가 여러 개 있거나, 이전 사용 결과가 미확정이거나, 알려진 형식과 맞지 않는 등록·기록이면 인계를 중단하고 기존 상태를 보존합니다. 등록 없이 따로 실행한 감시기나 다른 자동화 형식은 임의로 교체하지 않습니다. 일반적인 실행 순서와 설치 보호 장치는 [운영 문서](OPERATIONS.md)에 있습니다.

## 백업과 복구

통합 설치는 `~/Library/Application Support/CodexUsage/install-backups/<식별자>/`에 이전 앱과 실행 설정을 보관하고, 같은 지원 폴더의 `install-transaction.json`에 진행 상황을 기록합니다.

- 교체·실행 확인 중 실패하면 이전 앱과 실행 설정을 복구합니다. 설치 확인 동안 자동 사용과 알림은 비활성 상태입니다.
- 강제 종료 등으로 설치가 끊기면 같은 명령을 다시 실행할 때 미완료 작업을 먼저 복구합니다. 이미 설치를 확정한 뒤 활성화만 남은 경우에는 최신 사용 기록을 유지하면서 활성화를 마칩니다.
- 미완료 설치를 제거할 때는 자동 사용을 새로 활성화하지 않습니다.
- 복구 자체도 실패했다면 기록·백업을 보존하고 오류 원인을 확인한 뒤 다시 실행하세요. 완료된 버전을 임의로 과거 백업에 덮어씌우는 용도로 설치 기록을 수정하지 마세요.

`state.json`을 지우거나 오래된 사본으로 덮어쓰면 미확정 요청을 구분하는 정보가 사라질 수 있습니다. 통합 설치·제거·자동 복구는 현재 사용 기록을 보존합니다. 실제 운영 환경의 복구는 별도 확인이 필요합니다.

### 이전 인계 도구의 백업

과거 `reset-worker.py`로 만든 백업은 그 도구가 알려 준 경로와 절차로 복구합니다. 통합 설치의 `install-backups`와 서로 교환해서 사용할 수 없습니다. 다음 경로의 `EXAMPLE_TIMESTAMP`는 예시입니다.

```sh
python3 Scripts/reset-worker.py --rollback "$HOME/Library/Application Support/CodexUsage/backups/EXAMPLE_TIMESTAMP"
```

이전 도구는 최신 앱의 사용 기록을 이전 감시기의 기록에 반영한 뒤 원래 앱과 실행 설정을 복원합니다. 별도 절차로 만든 개인 환경의 백업은 당시 복구 도구를 보존해야 합니다.

## 상태 점검

다음 명령은 정보를 조회할 뿐 리셋권을 사용하지 않습니다. 예시는 직접 만든 앱의 경로입니다. 설치 앱을 점검하려면 실제 설치 위치로 바꾸세요.

```sh
.build/CodexUsage.app/Contents/MacOS/CodexUsage --print-usage
.build/CodexUsage.app/Contents/MacOS/CodexUsage --print-native-reset-status
.build/CodexUsage.app/Contents/MacOS/CodexUsage --notification-status
```

출력에는 개인 사용량과 만료 시각이 포함될 수 있습니다. 공개 이슈에 그대로 붙이지 말고 필요한 부분만 개인 정보를 가린 뒤 공유하세요. 로그인 파일·쿠키·토큰·실제 설정·사용 기록·로그·백업은 공개 저장소에 넣지 않습니다.

| 기본 위치 | 내용 |
| --- | --- |
| `~/Library/Application Support/CodexUsage/codex-path` | Codex CLI의 실행파일 위치 |
| `~/Library/Application Support/CodexUsage/reset/settings.json` | 자동 사용과 알림 설정 |
| 같은 폴더의 `state.json` | 사용 결과, 재확인할 요청과 보낸 알림 기록 |
| 같은 폴더의 `worker.json`, `ownership.json`, `wake.json`, 잠금 파일 | 감시 프로그램의 실행 설정과 중복 실행 방지 |
| 같은 폴더의 `worker.stdout.log`, `worker.stderr.log` | 개인 실행 로그 |
| `~/Library/LaunchAgents/<선택한 이름>.plist` | Mac 로그인 뒤 감시기를 실행하는 설정 |
| `~/Library/Application Support/CodexUsage/installation.json`, `install-transaction.json` | 설치 위치와 진행·복구 기록 |
| 같은 지원 폴더의 `install-backups/<식별자>/` | 통합 설치의 이전 앱·설정 백업 |
| 같은 지원 폴더의 `backups/<시각>/` | 이전 인계 도구가 만든 백업 |

설정과 사용 기록은 사용자만 읽을 수 있는 권한으로 저장합니다. 별도 설치 절차를 쓴 경우 위치가 다를 수 있습니다.

앱은 기존 Python 감시기 설정을 읽기만 하는 기능도 가지고 있습니다. 위의 이전 감시기 폴더나 `CODEX_USAGE_RESET_WATCHER_DIR`에 있는 정책·상태·일부 로그를 읽으며, Python 코드를 실행하지 않습니다. 앱으로 옮기기 전의 상태 확인과 가상 미리보기에 사용합니다.

## 결과가 불확실할 때의 처리

메뉴에 **‘소비 결과 확인 필요 · 추가 사용 보류’**가 보이면 사용 요청의 결과가 아직 불확실한 상태입니다. 감시 프로그램은 요청을 구분하는 번호를 먼저 저장합니다. 개발 코드에서는 이를 `idempotency key`라고 부릅니다. 통신이 끊겨 결과를 확인하지 못하면 **새 번호로 다른 권을 사용하지 않고**, 저장한 번호로 기존 요청만 재확인합니다.

재확인은 3분이 지난 뒤 최신 사용 조건이 맞을 때 시도합니다. 재시작해도 요청 번호와 보류 상태는 유지합니다. 권이 사라지거나 만료됐다고 성공을 추정하지 않습니다. 해당 요청에 대한 Codex 서비스 응답으로 결과가 확정돼야 합니다. 사용 성공 뒤에는 연속 사용을 줄이기 위해 5분간 기다립니다.

이 소비 보류와 알림은 별개입니다. 조회에서 확인된 다른 사용 가능한 권의 만료 알림은 계속 처리합니다. 한 번 보낸 단계의 알림 기록도 저장해 재시작 후 중복을 줄입니다.

메뉴의 사용량 갱신은 조회만 합니다. 실제 사용은 등록된 감시 프로그램 하나가 담당하며, 실행 설정 확인과 프로세스 잠금으로 중복 실행을 막습니다. 사용 기록을 지우거나 감시 프로그램을 두 개 실행하지 마세요. 복구할 때도 [최신 기록을 보존하는 절차](#백업과-복구)를 따릅니다.

## 로그인 정보와 통신

앱은 로그인된 `codex app-server --stdio`를 통해 OpenAI와 통신하며, 로그인 파일·쿠키·토큰을 직접 읽거나 복사하지 않습니다. 사용량을 자체 서버나 제3자에게 보내거나 새로운 AI 대화를 시작하지 않습니다. 통신 방식이 바뀌어 오류가 나더라도 로그인 파일 직접 접근이나 비공개 통신 주소 추측으로 우회하지 않습니다.

## 코드를 검사하고 앱 만들기

소스를 처음 받는 경우에는 다음을 사용합니다.

```sh
git clone https://github.com/yulepapa/codex-usage-menubar.git
cd codex-usage-menubar
make test
make build
```

`make build` 결과는 `.build/CodexUsage.app`입니다. 두 종류의 Mac 칩에서 실행할 수 있는 앱을 만들려면 `make universal`을 사용합니다. 앱은 Swift로 만들며 별도 실행 환경을 설치할 필요는 없습니다.

개발 도구가 준비됐는지 확인합니다.

```sh
xcrun swiftc --version
```

별도로 설치된 Command Line Tools를 이번 명령에만 선택해야 한다면 다음을 사용합니다. Mac의 전역 설정은 바꾸지 않습니다.

```sh
DEVELOPER_DIR=/Library/Developer/CommandLineTools make test
```

기본 `make test`는 가상 자료와 가짜 Codex 프로그램으로 검사하며 실제 권을 사용하지 않습니다. 선택적인 `make test-live`는 실제 계정의 **읽기 전용 사용량 조회**를 추가합니다.

### 가상 자료로 메뉴 미리보기

```sh
CODEX_USAGE_DEVELOPMENT=1 ./Scripts/build.sh .build/CodexUsageDev.app
open -n .build/CodexUsageDev.app --args --preview "$PWD/Tests/Fixtures/ResetPreview" --at 1893452400
```

2030년 가상 자료만 사용하고 실제 Codex CLI나 감시기에 연결하지 않습니다. 개발 앱은 별도 앱 식별자와 메뉴바 위치를 사용하며 설치된 앱을 대체하지 않습니다. 화면에는 샘플 데이터라고 표시됩니다.

실제 만료 배너, 실제 자동 사용, 재부팅·잠자기 복귀와 운영 복구는 가상 검사만으로 확인할 수 없습니다. 실제 점검을 완료했다고 가정하지 말고 [검증 문서](VALIDATION.md)에서 범위를 확인하세요.

- [보안 정책](../SECURITY.md): 개인 정보와 인증 정보 취급 원칙을 설명합니다.
