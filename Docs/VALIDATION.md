# Validation scope

The v1.1.0 runtime has 50 reset-status/time-zone checks and 29 engine checks, plus guarded mock stdio read and consume contract tests. All fixtures use fictitious data. The packaging check verifies an invalid-architecture build preserves the last good app. The portable migration tests use temporary paths and synthetic keys, never launchd or the real CLI.

Coverage includes standby, exact 10% thresholds, weekly-only eligibility, another bucket, changed credit/eligibility, missing/stale data, noCredit/nothingToReset/alreadyRedeemed, persisted intent failures, restart with the same key, exclusive process lease, reminders and denied notification permission. Asia/Seoul display is checked across a UTC date boundary.

A local v1.1.0 deployment verified the installed version, a single native worker with no legacy consumer, actual menu construction, current settings and macOS notification authorization. Personal usage values and logs are not published here. No real credit was consumed for verification.

Actual expiry-banner display, real conditional redemption, reboot/wake behavior and a live rollback are separate operational checks and have not been demonstrated by the synthetic tests. The portable generalized handoff has not been applied to the live deployment. The installed runtime sources remain byte-identical to the deployed v1.1.0 source snapshot.

The repository scan covers tracked working files and every reachable historical blob, commit/tag metadata, and historical filenames for credentials, personal absolute paths, runtime state/binaries and private endpoints. It is a scoped pattern review, not proof that every possible secret representation is impossible. Synthetic fixture IDs and recovery keys are intentionally fictitious.
