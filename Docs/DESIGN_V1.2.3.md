# 코코(COCO)의 이전 Codex Usage v1.2.3 팝오버 디자인 사양

## v1.2.6 주간 참고 눈금 추가

이 문서의 v1.2.3 레이아웃·색·서체를 이어 사용한다. 현재 앱은 v1.2.6/빌드 14이며, 주간 잔여량 막대의 검은 끝점만 제거하고 얇은 균등 기준 눈금을 겹친다. 5시간·리셋권 영역은 기존 규칙을 유지한다.

응답에서 `windowDurationMins == 10080`이고 `resetsAt`이 있을 때 `start = resetsAt − windowDurationMins × 60`, `timeLeft = (resetsAt − now) / duration`을 계산한다. 잔여량 축이므로 눈금은 `28 + 346 × timeLeft`다. 별도 시작 필드는 요구하지 않으며, 실제 길이가 없으면 7일을 임의로 가정하지 않는다. 구간 밖 시각·만료·조회 실패·오래된 값에는 숨긴다. 확인된 리셋 이후의 새 사용량 응답이 도착하면 반환된 길이·종료로 다시 계산한다. 리셋권 사용 시 서버의 구간 변경 방식은 이 참고선이 예측하지 않는다.

선은 `ink` 1.5pt, `white` 4pt 대비 테두리이며 막대 위 3pt부터 아래 3pt까지 표시한다. 위쪽 6pt 캡으로 기존 채움 끝과 구분한다. 기존 초기화 줄 오른쪽 `(368, gy+43)`에 `균등 기준` 11pt를 둔다. 전용 표시 버튼 `(28, gy−5, 346, 61)`은 툴팁·접근성 값으로 사용률 기준의 `±N%p`, 실제 구간 길이·종료와 산식을 설명하며 클릭하면 기존 상세를 연다. 참고선은 권장량·제한·소진 예측이 아니다. 색으로 빠름·느림을 경고하지 않는다.

`--export-popover-fixtures <directory> --offscreen`은 다른 앱의 화면을 활성화하지 않고 동일 뷰·표시 버튼을 검사한다. 이 옵션에서는 실제 NSPopover 열기/닫기 주기를 실행하지 않는다.

이 문서는 **v1.2.3 소스의 AppKit 구현을 재현하는 단일 디자인 기준**이다. 논리 좌표와 동작은 `Sources/CodexUsage/UsagePopover.swift`, 데이터·상태 문구는 `PopoverPresentation.swift`와 `ResetRuntime.swift`, 닫힌 메뉴바는 `main.swift`와 `StatusIcon.swift`에 근거한다. 아래 숫자와 색은 코드에서 확인한 값이며, 사용자 계정의 사용량·리셋권 수·만료일은 디자인 토큰이 아니다. 코드가 이후 바뀌면 코드를 검증한 뒤 이 문서를 갱신한다.

## 좌표·구조

모든 좌표는 화면 왼쪽 위가 `(0,0)`인 AppKit flipped view의 **pt**다. 팝오버는 고정 **660×414pt**, 모서리 반경 **22pt**, `#D7DCCF` 1pt 외곽선이다. Retina PNG는 1320×828px로 렌더된다. 이 버전에는 너비별 재배치·모바일 브레이크포인트가 없다. 긴 문구는 `maxWidth`를 넘으면 CoreText 글리프 너비를 기준으로 글자 크기를 비례 축소하며, 말줄임표는 넣지 않는다. 따라서 웹/영상 복제에서 임의 줄바꿈이나 크기 변경을 하면 실제 앱과 달라진다.

닫힌 메뉴바는 팝오버와 별도다. Codex 원본 SVG 경로를 18×18pt template 이미지로 그리고 macOS가 밝기·선택 상태의 색을 정한다. 제목은 한 구간이면 `42%`, 여러 구간이면 `5h 18% · 주 42%` 같은 **응답 기반** 값이며 0구간 `?`, 첫 조회 중 `…`, 첫 조회 실패 `!`다. 상태바 버튼의 시스템 글꼴과 가변 폭을 유지하고, Paperlogy/Pretendard 팝오버 글꼴을 적용하지 않는다. 구간·퍼센트 예시는 가상 값이다.

## 사용량·리셋권 배치와 경우의 수

사용량 구간은 `windowDurationMins`와 slot으로 정렬한다. `300`분은 `5시간 남음`, `10080`분은 `주간 남음`; 다른 길이는 모델의 실제 기간 라벨을 쓴다. 구간이 하나면 큰 숫자를 중앙에 배치한다: 라벨 `(28,106)`, 숫자 오른쪽 `(368,219)`, 막대 `(28,286,346,27)`, 초기화 `(28,329)`. 두 개면 행 시작 `y=106,234`, 숫자 중앙 `y=125,253`, 막대 `y=160,288`, 초기화 줄은 각 막대 아래 43pt다. 화면에는 처음 두 구간만 그리며 상세에는 전체 응답을 읽을 수 있다. 막대 채움 길이는 `346×remainingPercent/100`, 끝점 반경 2.6pt, 바탕·채움 높이 27pt/반경 13.5pt다. 사용량 구간이 없을 때 `정보 미제공` 또는 `확인 필요`와 빈 바탕을 표시하며 0%·무제한을 꾸며내지 않는다.

리셋권 앞카드는 반경 12pt이며 접힘 lime → 펼침 apricot으로 보간한다. `x=410/634,y=151`의 흰 원(반경 5.6pt)은 티켓 양쪽 타공, `y=152`는 4pt 선/5pt 간격의 절취선이다. 접힌 카드의 라벨 `(424,118)`·보유 수 오른쪽 `(620,134)`·만료 줄 `(424,164)`을 유지한다. 개별 유효권이 있으면 기본 카드가 **가장 빠른 만료**를 `1번 만료 · M/d HH:mm`(Asia/Seoul)로 직접 보인다. 연도가 현재 서울 연도와 다르면 `yy/M/d HH:mm`이다. 개별권이 없고 첫 만료만 알려지면 `첫 만료 · …`, 시각이 없으면 `만료 정보 확인`, 이미 지났으면 `만료 정보 재확인`이다. 숫자만 있는 응답으로 가짜 개별 카드를 만들지 않는다.

뒤 카드들은 실제 관측된 유효·중복 제거 ID별로 한 개의 `NSButton`을 가진다. 보이는 순서는 만료 오름차순, 같은 만료는 ID의 안정 정렬이다. 탭은 앞카드 뒤 `y=74…105`에 겹치며, 탭 직사각형은 x가 차례로 이동하는 `tabWidth−2 × 28pt`, 반경 7pt다. 너비 `max(44, 224/뒷카드수)`이므로 **전체 2~6장**은 한 줄에, **7장 이상**은 각 탭 최소 44pt를 지키며 224pt 뷰포트를 가로 스크롤한다. 카드 위치는 일반적으로 `1 / 2`, 7장 이상이면 `선택 1 / N · 좌우 스크롤`, 개수와 개별정보 수가 다르면 불일치 문구를 표시한다. 좌우 화살표는 `(410,246,28,20)`/`(606,246,28,20)` 버튼, 그려진 문자는 `‹`/`›`다. 비활성 끝점은 rule 색이다.

앞카드를 열면 높이가 83→139pt로 변하고 남은 기간·`지금`·서울 시각을 표시한다. 앞카드 기본 선택 상태에서 다시 클릭하면 접는다. 뒤 탭 클릭은 해당 ID를 앞면으로 올리며 바로 펼친다. 다른 카드가 앞에 있을 때 앞카드를 다시 누르면 **가장 먼저 만료되는 카드로 복귀하며 펼쳐진 상태**가 된다. 좌우 화살표와 키보드 화살표도 실제 ID를 이동시킨다. 갱신 후 선택 ID가 남아 있으면 유지하고, 사라지면 첫 카드로 복귀한다. 카드 hover는 해당 카드만 위로 **3pt** 올리되 클릭 영역 프레임은 움직이지 않는다. 어느 카드 선택·hover도 리셋권 소비나 설정 변경을 호출하지 않는다.

## 자동 사용·상태·상세

자동 사용 라벨은 `(410,277)` 25pt, 스위치 버튼은 `(545,268,89,42)`·반경 21pt다. 스위치 원 반경 16.6pt의 중심은 OFF `(566,289)` → ON `(613,289)`로 이동한다. `꺼짐/켜짐` 글자는 각각 오른쪽/왼쪽에 직접 표시하므로 색만으로 상태를 전달하지 않는다. 아래 상태 알약은 `(410,325,224,29)`·반경 14.5pt·ink 배경, `(425,339.5)` apricot 점 반경 3pt, 가운데 Paperlogy 18pt lime 상태명이다. 이 아래에 있던 상시 20분 정책 문장은 v1.2.3에서 제거됐고 상세 텍스트 `Mac이 깨어 있어야 함 · 만료 20분 이내 시도 · 잔여량 무관`에 있다.

상태명은 `PopoverPresentation.Status.title`을 그대로 쓴다. 우선순위는 미확정/보류 → 실패 → 초기화할 사용량 없음 → 최근 사용 완료·권 없음 → 보유 0/미확인 → 실행기 확인 → 자동 사용 꺼짐 → 만료됨/20분 이내/대기다. 대표 표기는 다음과 같다.

| 상태 | 화면 문구 |
| --- | --- |
| `pending` / `failed` | `결과 확인 · 사용 보류` / `조회·처리 확인 필요` |
| `nothingToReset` / `used` | `초기화할 사용량 없음` / `사용 완료` |
| `noCredit` / `unknown` | `보유 리셋권 없음` / `리셋권 확인 필요` |
| `setup` / `off` | `실행기 확인 필요` / `자동 사용 꺼짐` |
| `expired` / `ready` / `waiting` | `만료 정보 재확인` / `사용 시도 대상` / `만료 전 대기` |

알림은 상세의 `만료 전 Mac 알림` 체크박스로 바꾼다. `NativeResetSection.rows`는 실제 보유 수·만료·다음 자동 시도·최근 결과·오류·알림 권한·1시간/20분/5분 알림·20분 정책을 조건에 따라 나열한다. 카드·사용량의 시각은 Asia/Seoul이지만 이 감시기 처리 상세 행은 Mac의 현재 시간대를 사용한다. 마지막 결과가 `nothingToReset`이면 성공으로 바꾸어 말하지 않는다. 미확정·실패·알 수 없음도 임의로 사용 완료로 보이지 않는다. 개별권·사용량 정보가 최신인지 판단하는 현재 모델의 기준은 상태 확인 시각 **180초 이내**이며 조회 실패 시 수·카드를 미확인으로 돌린다.

## 움직임과 접근성

뷰의 타이머는 약 **60Hz**다. 카드 접힘/펼침 **0.40초**, 스위치 **0.25초**, 카드 hover **0.18초**이며 셋 모두 `t²(3−2t)` smoothstep easing을 쓴다. macOS Reduce Motion 또는 진단용 강제 설정이 켜져 있으면 진행도를 즉시 끝값으로 보낸다. 팝오버 시스템 애니메이션도 Reduce Motion이면 끈다. 영상 연출의 카메라 이동·확대·프레임레이트는 앱 동작으로 오해시키지 말고 별도로 표현한다.

그림 위에는 실제 `NSButton`이 얹혀 있어 Tab 순서와 클릭 경계가 유지된다. 앞카드의 VoiceOver 이름/값·툴팁에는 **권 번호, 전체 수, 서울 만료 시각, 펼치기/접기/첫 카드 복귀 동작**을 넣고, 뒤 탭도 번호·만료를 읽는다. 자동 사용 스위치는 켜짐/꺼짐을 이름과 1/0 값으로 읽고 툴팁은 누르면 바뀌는 설정과 20분 정책을 설명한다. 새로고침 글리프 `↻`는 이름 `사용량 새로고침`, 툴팁 `사용량 새로고침 (⌘R)`, 실제 88×25pt 클릭 영역을 유지한다. `⌘R` 새로고침, `⌘Q` 종료, Esc 닫기, 카드 좌/우 화살표·Enter·Space, 알림 체크박스와 상세 스크롤의 키보드 경로를 유지한다. 초점 링은 apricot 2pt/반경 8pt다. 상태는 알약 문구·경고 텍스트가 함께 있어 색만으로 구분하지 않는다.

## 재현·검수 절차

1. 이 문서와 위 네 Swift 파일의 **현재 버전**을 비교한다. 구 버전 스크린샷은 토큰의 출처로 쓰지 않는다.
2. 실제 계정 값이 아니라 가상 fixture를 사용한다. 예를 들어 진단의 5시간 18%·주간 42%·세 권(09:12/09:32/10:00 KST)은 합성 값이다. 실사용 계정의 사용률과 만료일을 고정 규칙으로 문서·영상에 넣지 않는다.
3. 비교 시 같은 폰트 파일, 660×414pt의 top-left 좌표, 동일한 상태·선택·확장 여부를 맞춘다. `--export-popover-fixtures`는 가상 데이터로 네이티브 PNG와 hit-test/키보드 진단을 만든다. 화면 캡처·실제 사용자 클릭·VoiceOver 발화·알림 배너·실제 리셋권 사용을 증명하지는 않는다.
4. 최소한 0/1/2/3/6/7+장, 유효/만료/미확인/실패/미확정/사용 완료, 단일/두 구간, 선택 복귀·hover·스크롤·Reduce Motion을 비교한다. 글리프 경계·정렬·클리핑·한국어 줄길이·접근성 이름을 확인한다.

프로젝트 전용 진입점은 `.agents/skills/reproduce-codex-usage-design/SKILL.md`다. 스킬은 이 문서를 읽어 시안·영상·구현을 대조하는 절차만 담으며 색·치수의 중복 사본을 만들지 않는다. 프로젝트 밖에 자동 설치되거나 실행되는 스킬은 아니다.
